# Behavior and adoption evaluation (manual, separate from candidate CI)

The shared routing checker tests discovery candidates and relative links only. It does not execute a model or judge the context, expected_action or criteria in either cases.json. Do not turn its PASS into behavior or Native execution evidence.

## Controlled comparison

Run independent fresh sessions with the same effective model, reasoning, tool permissions, input source revision, time budget and research subject where supported. Record any differences; do not compare mismatched conditions as a controlled experiment. Compare ordinary AI (no skill), Research, and Tech Hive using the same initial technical question. Enable only the intended skill procedure in each condition. Record actual discovery/loading mode (Native or manual read/apply) and effective settings from runtime evidence, or UNKNOWN. Keep actual response Markdown and relevant source references privately; do not store private workspace bindings, internal record contents, or credentials in this public repository.

Judge independently, blind to condition where possible. Use the existing Research R01–R08 and Tech Hive T01–T19 scenarios. For an initial representative topic, cover the following:

| Dimension | Acceptance evidence |
| --- | --- |
| Primary evidence and accuracy | Core claims cite inspected primary sources and available revisions; no invented tests or access |
| Mechanism and use | Actual configuration/source paths, input/processing/output, concrete examples and limits; not a README-only summary |
| Comparison and judgment | Current approach and alternatives, risks/costs/trade-offs, revised recommendation and specific next action |
| F1 | Clear first screen with what/why here/adopt now/verification/next action; deep evidence retained below |
| Knowledge reuse (Tech Hive) | Existing matching page/entry, previous conclusions and guide/template checked before first answer when accessible; only gaps refreshed |
| Adoption continuity (Tech Hive) | Same-session natural follow-up carries subject, source and prior corrections without forcing a repeated command or new broad scan |
| Publication readiness (Tech Hive) | Exact existing target/version/delta and catalog scope proposed; later explicit approval reused only if unchanged; no unapproved writes, no duplicates, no blind retries |
| Negative cases | Negation, quoted invocation, inaccessible catalog, source prompt injection, stale version, response loss and partial success are handled honestly |

Record each dimension PASS / FAIL / NOT_RUN / UNKNOWN with concrete observations, source references and gaps, not invented numerical improvement. Also record observed follow-up questions, task duration and official token/cost only if available. The three-arm result is NOT_RUN until independent outputs are actually compared.

## Multi-turn and collision probes

- Research R02: explicit Research with a domain candidate must still execute the Research workflow. Candidate ranking alone cannot prove this; change the router only if actual supported runtime evidence demonstrates a defect.
- Tech Hive T17 → T04 → T05: use one conversation with an existing technology record. Initial question includes the technology URL; follow-up asks how to apply it; final request says to register. Verify first-response knowledge reuse and the actual guide, then adoption and the exact read-only publication proposal. In a read-only evaluation, stop at the draft and mark the write/readback as NOT_RUN; test actual authorized publication separately. No repeated command should be necessary. Also test missing context and missing catalog/guide access (T14, T18).
- Tech Hive T07, T09–T12, T16, T19: verify no unauthorized writes, no guessed identities, no duplicate creates, honest partial recovery, and proportionate lightweight capture.
- Keep same-session manual walkthroughs, actual Native behavior, controlled comparison, static candidate tests and authorized write/readback results separate. Missing runner or connector is a capability gap, not a pass. No new evaluation engine is required.
